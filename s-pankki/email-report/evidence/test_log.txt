================================================================================
C) How the accountId reaches an attacker
================================================================================
- It is in the URL of EVERY account-related page (account page, tx detail, report,
  export, PAD form) -> leaks via:
    * Referer/Origin-less is NOT the issue: with default browser settings Referer:
      https://online.s-pankki.fi/ebank/... IS sent to other origins (e.g. when the
      victim pays via a cross-domain widget / clicks out while on an account page);
    * browser history & bookmarks (user bookmarks "my account");
    * screenshots, screen share, support chat;
    * any third-party widget/analytics that gets the full URL.
- accountId is 64 hex chars (salted/derived, NOT a hash of the IBAN — all simple
  hash combos tested and rejected) -> not enumerable by brute force, but once
  LEAKED it is permanent and sufficient.
- Validity can be confirmed with the oracles in A (getReport PDF vs 509B error) and
  B.3 (302 vs error) — no session kill, no rate-limit tripped (single probe).

================================================================================
D) Cross-site angle (same user, no other account needed)
================================================================================
- JSESSIONID: SameSite=None; Secure; HttpOnly; path=/ebank
  => the session cookie IS sent on cross-site GETs.
- getReport.ds is a tokenless plain GET returning a downloadable PDF.
  A cross-site top-level navigation (link on attacker page / window.open) executes
  GET /ebank/pad/fees/getReport.ds?accountId=<victim's accountId>&year=<Y> with the
  victim's session cookie -> the victim's browser downloads/opens the PDF that the
  server generated for the accountId in the URL.
- Combined with accountId leakage (C), an attacker who knows the victim's accountId
  does not even need the victim's session to be "active": with the victim's own
  browser state (e.g. via a link the victim clicks, or an attacker session in
  vector A), the report is produced. See poc/xsite_pdf_steal.html.
